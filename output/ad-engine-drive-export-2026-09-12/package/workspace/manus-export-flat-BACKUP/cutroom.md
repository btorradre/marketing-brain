# Visual Storyboard Briefs

This document describes a methodology for turning a reference video ad into a visual storyboard — a beat-by-beat breakdown laid out as parallel timelines (the reference creative alongside the planned adaptation), with frame screenshots, exact spoken/on-screen copy, and emotion/direction notes for each beat — intended as an editor-facing brief. Use this whenever a reference ad needs to be broken down visually for a team or an editor, rather than delivered as a plain text brief: e.g. "break down this reference into a storyboard," "map this reference visually," or any request to turn a reference video or creative concept into a visual brief a team or editor can review together. The output can be built as a simple visual document or slide-style page (an HTML page, a slide deck, or any shared visual board tool available in the working environment) — the structure and rules below are what matters, not the specific tool used to render it.

## Workflow — the main job: reference breakdown

Given a reference video (URL or local file):

1. **Watch it properly first.** Download it (or work from the provided file), extract frames at each scene change, and pull a full timestamped transcript of the spoken audio and any on-screen text. Never brief a reference that hasn't actually been reviewed frame-by-frame — a breakdown built from a vague memory of "what the ad is about" misses the specific beats that make it work.

2. **Segment the video into beats.** A beat is one visual idea — usually one scene or shot, roughly 1-5 seconds long. For each beat, capture:
   - **Timecode** — the range, e.g. "0:00-0:03".
   - **Script** — the exact spoken line, voiceover, or on-screen text during that beat, verbatim.
   - **Frame** — the single clearest representative frame for that beat (pick the clearest frame, not simply the first frame of the beat).
   - **Visual** — one line describing literally what's on screen: shot type, subject, motion.
   - **Emotion** — the emotion the beat conveys, AND its direct-response function: hook / pattern interrupt / problem agitation / proof / demonstration / call-to-action. This is the part an editor actually reads to understand *why* the beat exists, not just what it shows.
   - **Note** (optional) — a specific direction, e.g. "hold half a second longer than feels natural," "hard cut, no transition."

3. **If adapting the reference for a specific brand, load that brand's context first** (product truth, voice rules, existing research) before writing the adaptation. Then add a second parallel timeline — "our version" — with the adapted beats alongside the reference timeline. The adapted beats can describe the intended visual in words, or point at already-generated reference imagery if any exists.

4. **Assemble the visual document.** Lay out the two timelines side by side (or stacked, clearly labeled) so a viewer can compare beat-for-beat what the reference did against what the adaptation will do. Include a short one-paragraph summary at the top the editor reads first: the concept, the angle, and the target emotional arc across the whole piece.

5. **Deliver the finished visual document** as the actual deliverable — not a text description of what it should contain.

## Suggested content structure for the visual document

- **Title** — a short name for the storyboard/concept.
- **Summary** — one paragraph: concept, angle, target emotion arc across the ad.
- **Timeline 1: Reference Creative** — source note (where it's from, any performance context like view count if known), then the ordered list of beats as specified above.
- **Timeline 2: Our Version** (if adapting) — the same beat structure, adapted.
- **Notes** — short callout notes, e.g. a "DO" list and a "DON'T" list, called out visually (e.g. distinct background colors) so they're easy to scan.
- **Moodboard** (optional) — supporting reference images with a one-line caption on each (grade/texture reference, wardrobe reference, etc.).

## Editor-brief laws — non-negotiable

- **No local file paths anywhere on the finished board.** Frame images should be embedded directly into the document as images; an editor should never need to resolve a file path on their own machine. Notes should reference beats by timecode, never by an internal filename.
- **The emotion note is the actual brief.** Each beat's emotion/note must say what the viewer should *feel* and what job the beat is *doing* in the ad (hook / proof / demo / CTA) — not simply restate the visual description a second time. This is the single most valuable field on the whole board; don't let it go generic.
- **Script/copy cards carry the exact words**, never a paraphrase. If the reference says something specific, quote it exactly.
- Keep prose notes brief — a note that needs more than a sentence or two to make its point usually belongs as a longer note in the summary section instead of crammed into a single beat's card.

## Sharing the finished board

Once built, the visual document is the deliverable — share it as a link (if built as a web page) or an exported file the team/editor can open directly, rather than describing its contents back in chat. If real-time collaborative editing is needed (the team dragging cards around, adding their own notes), use whatever shared-canvas or whiteboard tool is available in the working environment for that purpose — the beat structure and laws above are what should be preserved regardless of which specific tool renders the final board.
