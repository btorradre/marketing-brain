# Video Editor Brief Generator

Companion skill to the video-scene-replicator. Takes a script + replicator output, uses Gemini to match every script line to the correct scene, and produces a full production brief for the video editor. **All briefs are published to Notion** as database entries with each script line paired with its corresponding scene screenshot.

## When to Use

Use this skill when:
- The user has a script (ad copy, VSL, UGC script) AND replicator output (from video-scene-replicator)
- The user says "create a brief", "match the script to the scenes", "make an editor brief", "brief for the video editor"
- The user wants to pair script lines with the B-roll clips generated by the replicator
- The user has run the replicator and now needs to hand off to a video editor

## Required Inputs

1. **Script** — either a file path or pasted text. Can be ad copy, VSL script, UGC script, talking head script, etc.
2. **Replicator output directory** — path to a previous video-scene-replicator run (contains `analysis/`, `animated/`, `generated/`, etc.)
3. **Brand name** (optional) — for the brief header
4. **Title** (optional) — video title for the brief header
5. **Google Drive folder ID** (optional) — uploads the brief to Drive alongside the B-roll
6. **Notion database ID** — for publishing briefs to Notion (required for `--notion` flag)

## How to Run

### With Notion publishing (default workflow):
```bash
python3 ~/.claude/skills/video-editor-brief/brief_generator.py \
  --script "/path/to/script.txt" \
  --replicator-dir "./replicator-output" \
  --brand "Motilli" \
  --title "GLP-1 Claymation Ad" \
  --notion \
  --angle "Metabolism Angle" \
  --format-type "Claymation" \
  --drive-folder "FOLDER_ID" \
  --output "./editor-brief.md"
```
Briefs auto-publish as child pages under the **Briefs** page (`334c96bf99828053b6b6f47e5897590b`). No `--notion-db` needed.

### Without Notion (markdown only):
```bash
python3 ~/.claude/skills/video-editor-brief/brief_generator.py \
  --script "/path/to/script.txt" \
  --replicator-dir "./replicator-output" \
  --brand "Motilli" \
  --title "GLP-1 Claymation Ad"
```

### With inline script:
```bash
python3 ~/.claude/skills/video-editor-brief/brief_generator.py \
  --script-text "Ever since I started taking GLP-1..." \
  --replicator-dir "./replicator-output" \
  --brand "Motilli" \
  --notion
```

**Dependencies:** `pip install google-genai requests` (same as replicator + requests for Notion API)

**Environment:** `NOTION_TOKEN` is hardcoded in `notion_brief.py` and also configured in `~/.claude/settings.json` via the notionApi MCP server. The default Briefs parent page (`334c96bf99828053b6b6f47e5897590b`) is hardcoded — no need to pass a database/page ID.

## What It Does

### Stage 1 — Load Replicator Output
Reads `scene_analysis.json`, `image_prompts.json`, scans `animated/` and `generated/` directories to build a full scene inventory with file references.

### Stage 2 — Parse Script
Splits the script into logical segments by:
- Scene markers (`[SCENE 1]`, `SHOT 1`, `CUT TO`, `---`)
- Double newlines (paragraph breaks)
- Single newlines (line-by-line) as fallback

### Stage 3 — Match Script → Scenes via Gemini
Sends the full script + all scene analyses to Gemini. Gemini sees each scene's description, composition, mood, key_elements, and motion — and produces an intelligent 1:1 mapping. Matching considers:
- Narrative alignment (mood/description matches script content)
- Visual relevance (key_elements match what the script describes)
- Pacing flow (maintains video timeline order)
- Product scenes match product-mention lines
- Scenes can be reused if needed; extra scenes flagged as cutaway B-roll

### Stage 4 — Generate Brief
Produces a structured markdown brief with:
- **Header** — brand, date, title, scene/segment counts, estimated duration
- **Timeline table** — scene-by-scene with timestamps, durations, script previews, file references, match confidence
- **Scene-by-scene direction** — full script text, visual description, composition, motion, mood, style, file paths, editor notes from Gemini
- **Extra B-roll** — unmatched scenes the editor can use as cutaways/transitions
- **Pacing guide** — total duration, average scene length, pacing recommendation
- **Asset manifest** — every file the editor needs (animated clips, stills, keyframes)
- **Full script** — numbered segments for reference

### Stage 5 — Google Drive Upload (optional)
Uploads the brief `.md` file to the same Drive folder as the replicator output. Reuses the replicator's OAuth2 token — no re-auth needed.

### Stage 6 — Notion Publishing (when `--notion` flag is set)
Creates a Notion database entry with:

**Database Properties:**
- **Title** — video title
- **Brand** — brand name (select)
- **Date** — creation date
- **Status** — "In Review" (select: Draft / In Review / Approved / Published)
- **Angle** — creative angle (rich text)
- **Format** — format type like UGC, Claymation, Talking Head (select)
- **Scene Count** — number of scenes (number)
- **Script** — full script text (rich text, truncated to 2000 chars)

**Page Body — Script Line + Scene Image Pairs:**
Each script segment is rendered as:
1. A callout block with the script line text and segment number
2. An image block showing the brand-adapted still from `generated/` (uploaded to Google Drive for hosting)
3. Editor notes in gray italic text (scene number, confidence, direction)
4. A divider between segments

Images are uploaded to Google Drive (reusing the replicator's OAuth2 token) and referenced as external URLs in Notion.

## Output Format

The brief is designed for a human video editor to follow sequentially. Each scene block gives them:
- Exact script line to match to audio
- Visual direction (what the scene looks like)
- Motion notes (camera movement, subject action)
- The exact filename of the B-roll clip and still
- Editor-specific notes from Gemini on how to use the scene

## Typical Workflow

1. Run `video-scene-replicator` on a reference video → produces B-roll in `./replicator-output/`
2. Write or paste the ad script
3. Run `video-editor-brief` with `--notion` flag → generates markdown brief AND Notion page
4. **Claude presents a summary** (script lines, scene count, brand, title) and asks for confirmation before publishing to Notion
5. On approval, brief is published to Notion with script lines paired with scene screenshots
6. Video editor opens the Notion brief, follows it scene-by-scene, assembles the final video

## Review-Before-Publish Flow

**IMPORTANT:** When running this skill, Claude should ALWAYS:
1. Generate the markdown brief first (stages 1-5)
2. Show the user a summary: number of script segments, scenes matched, brand, title
3. Ask: "Ready to publish this brief to Notion? (Brand: X, Title: Y, Segments: N, Scenes: M)"
4. Only run the Notion publishing step (stage 6) after the user confirms
5. Return the Notion page URL once published

This ensures the user reviews the brief before it goes to the editor in Notion.
